**Décision de véhicule (2026-08-03, discutée avec l'utilisateur)** : migration future via **pioarduino** (empaquetage communautaire du core officiel — le code embarqué reste 100 % Espressif ; déjà en prod sur le projet écran). Plan B documenté sans surcoût : « Arduino comme composant ESP-IDF » (officiel, accès sdkconfig → tuning lwIP possible). Sortir de PlatformIO écarté : perdrait `pio test -e native` (415 tests) et l'outillage pour la même dette d'API.

**Motivations** : plateforme actuelle abandonnée (espressif32@6.9.0 = core 2.0.17/IDF 4.4.7, plus aucun correctif) ; wedge lwIP (confinement ADR-0030 — IDF 5 = lwIP récent) ; bug littlefs div/0 corrigé en amont (ADR-0033).

**Spec d'étude prête** : `specs/features/todo/feature-062-etude-migration-core3-idf5.md` — étude SANS toucher la prod : inventaire ruptures (LEDC = pompes → pool-chemistry obligatoire à l'exécution ; esp_task_wdt_config_t ; événements WiFi ; esp_ping ; RTC_NOINIT ; fork Async ; flags CONFIG_LWIP_*), banc de compilation isolé, 4 questions critiques (littlefs corrigé ?, FS partition compatible ?, NVS préservé ?, retour arrière ?), plan banc matériel (pompes à vide, verre doseur).
